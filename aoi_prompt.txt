IMPORTANT:
Do NOT treat this as a simple bounding-box detection problem.

The AOI must represent the ACTUAL DIG AREA ON THE MAP.

The following rules are mandatory.

==================================================
1. PRIMARY AOI RULE
==================================================

The AOI must be derived from the actual map's dig-site geometry.

If the map explicitly contains an AOI / DIG SITE / SITE BOUNDARY / WORK AREA boundary, that boundary is authoritative.

Examples include:

- red "AOI SITE BOUNDARY"
- red rectangular dig-site boundary
- circular dig area
- polygonal dig area
- other clearly marked work/dig boundary

The detector must identify and use the actual boundary geometry.

Do NOT automatically create a rectangular page/image bounding box around detected content.

==================================================
2. CIRCULAR DIG AREA
==================================================

This is especially important.

If the source map shows a circular dig area, the generated AOI MUST also be circular.

Do NOT convert:

    circle → bounding rectangle

Do NOT use:

    circle → arbitrary polygon approximation that materially changes the boundary

The AOI should preserve the detected circle's:

- center
- radius
- shape
- position
- scale

The resulting AOI must be spatially aligned with the circle shown on the map.

The circle must be mapped to the correct map coordinate/pixel space.

==================================================
3. RECTANGULAR / POLYGONAL DIG AREA
==================================================

If the source map contains a rectangular or polygonal AOI boundary:

- detect its actual boundary
- preserve its geometry
- preserve its orientation
- preserve its position
- do not expand it unnecessarily
- do not clip it incorrectly

The AOI should follow the actual boundary rather than creating a generic padded rectangle.

==================================================
4. AOI MUST NOT INCLUDE LEGENDS OR PAGE FURNITURE
==================================================

This is currently a major problem.

The AOI must represent ONLY the actual map/dig area.

Never include:

- legend
- key to symbols
- title block
- company logo
- disclaimer
- copyright text
- contact details
- email address
- QR code
- warning text
- scale bar
- north arrow
- page footer
- document header
- metadata tables
- map notes outside the actual map
- document borders

For example, if a map has:

    ┌─────────────────────────────┐
    │         HEADER              │
    │                             │
    │   ┌─────────────────────┐   │
    │   │                     │   │
    │   │     ACTUAL MAP      │   │
    │   │                     │   │
    │   └─────────────────────┘   │
    │                             │
    │ LEGEND / DISCLAIMER / FOOTER│
    └─────────────────────────────┘

the AOI must be restricted to the ACTUAL MAP region.

It must NOT include the legend/footer.

==================================================
5. DISTINGUISH PAGE REGION FROM MAP REGION
==================================================

Introduce an explicit concept of:

    PAGE_REGION
    MAP_REGION
    DIG_AOI

These are NOT the same thing.

Pipeline:

    PDF PAGE
       ↓
    identify actual MAP REGION
       ↓
    detect DIG/AOI boundary inside MAP REGION
       ↓
    construct DIG_AOI
       ↓
    run downstream spatial/QA analysis

Do not use the entire PDF page as the AOI.

If the PDF contains a map plus legend/footer/header, first isolate the map region.

==================================================
6. NO DIG SITE PRESENT
==================================================

This rule is mandatory:

If no explicit dig-site/AOI boundary is present on the map, then:

    DIG_AOI = entire ACTUAL MAP REGION

NOT:

    DIG_AOI = entire PDF page

NOT:

    DIG_AOI = page border

NOT:

    DIG_AOI = legend + map + footer

Instead:

    DIG_AOI = map viewport/content region only.

==================================================
7. RED AOI BOUNDARY
==================================================

Many of these engineering maps use a red boundary labelled:

    AOI SITE BOUNDARY

Treat this as a high-confidence AOI signal.

The detector should:

1. detect the red boundary
2. determine whether it is an AOI/site boundary
3. extract its actual geometry
4. map the geometry into the PDF/image coordinate system
5. create the AOI from that geometry

Do not simply detect red pixels and calculate a loose bounding box.

The geometry should be reconstructed from the boundary itself.

==================================================
8. IMAGE + PDF VECTOR HYBRID
==================================================

Use the strongest available evidence.

Priority should be approximately:

    1. PDF vector geometry / explicit AOI boundary
    2. clearly detected map boundary
    3. CV geometry detection
    4. OCR/text evidence such as "AOI SITE BOUNDARY"
    5. other visual inference
    6. AI/ML only as supporting evidence

AI MAY be used to help identify the map region or boundary.

However:

AI MUST NOT be the sole authority for the final AOI.

The final AOI must be deterministic/validated.

==================================================
9. PDF COORDINATE SYSTEM
==================================================

Be extremely careful about coordinate transforms.

PDF coordinates and rendered-image coordinates may have different:

- origin
- Y direction
- scale
- DPI
- page dimensions

Therefore:

    PDF geometry
          ↓
    coordinate transform
          ↓
    rendered image
          ↓
    detected AOI

must preserve exact spatial alignment.

A circle in PDF space must remain a circle in the corresponding map coordinate system.

A rectangle must not shift or stretch.

==================================================
10. AOI VALIDATION
==================================================

After detecting an AOI, run deterministic validation.

At minimum validate:

- AOI is inside the map region
- AOI does not include legend region
- AOI does not include footer/header
- AOI does not include document furniture
- AOI has valid geometry
- AOI has non-zero area
- AOI is within page bounds
- AOI is spatially aligned with the source boundary
- AOI does not extend outside the detected dig boundary
- geometry type is preserved where confidently detected

For a detected circular AOI:

    geometry type = circle / circular geometry

For rectangular AOI:

    geometry type = polygon/rectangle

For polygonal AOI:

    geometry type = polygon
